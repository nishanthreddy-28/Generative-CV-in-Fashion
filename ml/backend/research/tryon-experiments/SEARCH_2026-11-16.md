# Search for a replacement photo try-on model

Target: a recognizable person wearing the selected garment(s), natural folds and occlusion, preserved prints/logos, and one final image. Prioritize free hosted inference. The bad FitDiT result is evidence that a successful API call alone is insufficient.

No application provider was changed during this search. Network probes used public FitDiT example photographs only, without a Hugging Face token or paid endpoint.

## Actual Qwen joint generation

- Person input: public FitDiT example, gray T-shirt and beige shorts.
- Reference board: public GANNI star knit sleeveless top beside blue logo jeans, combined only as a model input. No garment pixels were overlaid onto the person.
- Settings: one megapixel, 25 steps, seed 42. One remote model generation for both garments, not sequential try-on passes.
- Output: `qwen_21_joint_1.webp`; resized before image: `qwen_21_joint_0.webp`; reference: `public_outfit_board.jpg`.
- Visual inspection: both garments transferred, recognizable face/framing/pose retained, hands and original shoes remain coherent. Main star/lettering and both jean motifs are recognizable. Fine knit structure and logo geometry still have differences, so this is not pixel-exact product reproduction.
- This single test uses clean product photographs. It does not establish performance on the user's model-worn teal T-shirt and jeans references, which contain skin and shoes.
- Earlier Qwen request was blocked by quota. Later request succeeded; access can change with quota/session state. Do not infer unlimited or reliable production service from this one call.

## Free hosting versus free API use

Current ZeroGPU documentation permits free usage of existing Spaces with quotas. It also permits qualifying free personal accounts (verified email, account older than 30 days and in good standing) to host up to two ZeroGPU Spaces. This makes a user-owned hosted deployment a possible route; compatibility and model access must still be checked. This does not imply unlimited inference or guaranteed availability.

API metadata and schemas: `new_candidates_2026-11-16.json`. Probes: `flux_klein_joint_api_smoke.json`, `firered_11_joint_api_smoke.json`, `qwen_21_joint_api_smoke.json`. Standard Gradio queue diagnostics distinguish quota/worker errors from visual model failures.
